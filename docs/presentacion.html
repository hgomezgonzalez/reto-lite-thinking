02 Objetivo y stack tecnológico

Aplicación que gestiona Empresas, Productos (precio en varias monedas), Inventario con descarga de PDF y envío por correo, login y dos roles (Administrador / Externo).

Backend

Java 17 Spring Boot 3.3

Spring Security (JWT), Hibernate/JPA, Flyway, OpenPDF, JavaMailSender, springdoc/Swagger.

Frontend

Base de datos

PostgreSQL

Esquema versionado con Flyway; esquema propio reto_lite.

Prácticas aplicadas

Clean Architecture · principios SOLID · Clean Code · patrón Puertos&Adaptadores · DTOs · pruebas unitarias · documentación técnica · CI/CD.

04 Backend — Clean Architecture (4 capas)

La regla de dependencia apunta siempre hacia adentro: lo externo conoce lo interno, nunca al revés.

presentation — Controladores REST + manejo global de errores AuthController, EmpresaController, ProductoController, InventarioController, GlobalExceptionHandler
application — Casos de uso, DTOs, puertos, mappers AuthService, EmpresaService, ProductoService, InventarioService · interfaces CurrencyConverter / EmailSender / PdfGenerator
domain — Entidades y reglas del negocio Empresa, Producto, Categoria, Cliente, Orden, OrdenItem, Inventario, Usuario
infrastructure — Adaptadores (implementan los puertos) JPA repositories · JWT/Security · SmtpEmailAdapter · OpenPdfAdapter · ExchangeRateApiAdapter

Beneficio: puedo cambiar la base de datos, el proveedor de correo o la API de tasas sin tocar la lógica de negocio. Y pruebo los servicios sin levantar infraestructura.

04b Cómo se ven los principios SOLID

S — Responsabilidad única

JwtTokenProvider solo emite/valida tokens; OpenPdfAdapter solo arma el PDF.

O — Abierto/Cerrado

Añadir otro proveedor de correo = nuevo adaptador, sin modificar los servicios.

L — Sustitución de Liskov

Cualquier CurrencyConverter es intercambiable; respeta el contrato.

I — Segregación de interfaces

Puertos pequeños y específicos en vez de una interfaz gigante.

D — Inversión de dependencias (clave)

application depende de interfaces (puertos); Spring inyecta la implementación concreta de infrastructure en tiempo de ejecución.

// application/port — la abstracción
public interface CurrencyConverter {
    Map<String, BigDecimal> convertToAll(BigDecimal amount, Moneda base);
}
// infrastructure — el adaptador concreto (API REST + fallback)
class ExchangeRateApiAdapter implements CurrencyConverter { ... }

05 Modelo entidad-relación

Entidades solicitadas y sus relaciones:

  • Empresa (NIT como llave primaria) 1—N Producto
  • Producto N—M Categoría (tabla producto_categoria)
  • Cliente 1—N Orden
  • Orden N—M Producto vía orden_item
  • Inventario: producto por empresa (stock)
  • Usuario: email, hash BCrypt, rol

Decisión de diseño

La relación Orden↔Producto se modela con la entidad intermedia OrdenItem porque tiene atributos propios (cantidad y precio unitario): es un N—M “enriquecido”.

Manejo del esquema

El DDL vive en V1__schema.sql y los datos demo en V2__seed_demo.sql, aplicados por Flyway al arrancar. Hibernate queda en ddl-auto=none (el esquema lo controla la migración, no el ORM → práctica de producción).

-- N—M Producto <-> Categoria
CREATE TABLE producto_categoria (
  producto_id  BIGINT REFERENCES producto(id),
  categoria_id BIGINT REFERENCES categoria(id),
  PRIMARY KEY (producto_id, categoria_id)
);

Autenticación

La contraseña se guarda siempre encriptada con BCryptPasswordEncoder. Tras validar, JwtTokenProvider emite un token con el rol como claim.

Autorización por rol

JwtAuthenticationFilter valida el token en cada request. SecurityConfig define: lectura para ADMIN y EXTERNAL, escritura solo ADMIN. Sesión stateless.

// SecurityConfig — reglas declarativas
.requestMatchers(GET,  "/api/**").hasAnyRole("ADMIN", "EXTERNAL")
.requestMatchers(POST, "/api/**").hasRole("ADMIN")   // crear
.requestMatchers(PUT,  "/api/**").hasRole("ADMIN")   // editar
.requestMatchers(DELETE,"/api/**").hasRole("ADMIN")   // eliminar

07 Multimoneda, PDF y correo (puertos y adaptadores)

Precio multimoneda

Se guarda precioBase + monedaBase; se convierte al vuelo a COP/USD/EUR. No se duplica el precio por moneda (evita desincronización).

Strategy / Adapter

API REST pública de tasas + fallback a tasas estáticas + caché de 1h.

PDF de inventario

OpenPdfAdapter genera una tabla corporativa con membrete y pie con los datos de contacto.

GET /api/inventario/pdf

Envío por correo

SmtpEmailAdapter (JavaMailSender) adjunta el PDF y lo envía. MailHog en local, Gmail (App Password) en producción.

POST /api/inventario/pdf/email

Los tres son adaptadores que implementan puertos definidos en la capa de aplicación → tolerancia a fallos y reemplazo sin tocar la lógica.

08 Frontend — Quasar / Vue 3

Estructura

  • layouts/MainLayout — header, menú por rol y footer con los datos del autor
  • pages/ — Login, Empresas, Productos, Inventario
  • stores/auth (Pinia) — token + usuario + isAdmin
  • router — guards que protegen rutas y bloquean admin a externos
  • services/api — Axios con interceptor que adjunta el JWT

Manejo de sesión y permisos

// interceptor: token en cada petición
api.interceptors.request.use(cfg => {
  const t = localStorage.getItem('token')
  if (t) cfg.headers.Authorization = `Bearer ${t}`
  return cfg
})
// guard del router por rol
if (to.meta.adminOnly && !auth.isAdmin)
  return { path: '/empresas' }

El externo ve la lista pero no los botones de crear/editar/eliminar; el backend además lo bloquea con 403 → seguridad en ambas capas.

12 Levantar el proyecto en local (paso a paso)

Requisitos

Java 17+, Maven, Node 18+, PostgreSQL. (Opcional: Docker, MailHog.)

① Base de datos local

# crear rol y base de datos
psql -c "CREATE ROLE reto_user LOGIN PASSWORD 'reto_pass';"
createdb -O reto_user reto_db
# el esquema reto_lite y los datos demo
# los crea Flyway al arrancar (no hay que crearlos a mano)

② Variables de entorno (backend)

export JDBC_DATABASE_URL=jdbc:postgresql://localhost:5432/reto_db
export JDBC_DATABASE_USERNAME=reto_user
export JDBC_DATABASE_PASSWORD=reto_pass
export DB_SCHEMA=reto_lite
export SMTP_HOST=localhost  SMTP_PORT=1025   # correo local

③ Backend

cd backend
mvn spring-boot:run        # http://localhost:8080
# Swagger: http://localhost:8080/swagger-ui.html

④ Frontend

cd frontend
npm install
npm run dev                # http://localhost:9000
# el proxy /api apunta al backend :8080

⑤ SMTP de pruebas (para el envío del PDF)

python3 -m smtpd -n -c DebuggingServer localhost:1025
# o MailHog -> bandeja en http://localhost:8025

Todo en un comando con Docker: docker compose up --build (Postgres + MailHog + backend + frontend).
